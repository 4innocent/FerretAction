# 基于 CPU 的屏幕目标低延迟检测方案

## 1. 概述

本文档描述一种在 Windows 平台上实现的低延迟屏幕目标检测方案。方案借鉴 Airtest 框架中 **mstpl（多尺度模板匹配）** 算法的核心策略，采用 **ORB 特征点** 替代 SIFT/SURF，结合 **图像金字塔** 实现尺度自适应。整个处理管线完全在 CPU 端完成，针对 2K 分辨率屏幕优化，可将端到端延迟控制在 20 毫秒以内。

## 2. 背景与动机

在 UI 自动化测试、游戏辅助、实时监控等场景中，需要在屏幕上快速定位预设的目标（如按钮、图标、角色）。核心需求包括：

- **低延迟**：从画面出现到定位完成的延迟应小于 20ms，保证实时交互体验。
- **鲁棒性**：能够应对目标的轻微旋转、缩放、部分遮挡及光照变化。
- **可部署性**：无需 GPU 辅助，依赖尽量少，便于集成到各类应用中。

mstpl 通过多尺度搜索和 SIFT/SURF 特征点匹配实现了较高鲁棒性，但 SIFT/SURF 计算量大且有专利风险。本方案选择 ORB 作为特征描述子，利用其无专利、极快的特点，并配合图像金字塔补足其尺度不变性的不足，在保证检测效果的同时大幅降低运算开销。

## 3. 系统总体架构

系统采用流水线设计，由四个核心模块顺序组成：

1. **屏幕捕获模块** —— 获取当前屏幕的像素数据。
2. **图像缩放模块** —— 将高分辨率画面压缩至检测尺寸，降低后续处理负担。
3. **多尺度特征匹配模块** —— 在多个缩放层级上提取 ORB 特征并与模板比对。
4. **几何验证与定位模块** —— 剔除错误匹配，输出目标在原图中的位置与范围。

数据流方向为：**屏幕 → BGRA 缓冲 → 缩放图像 → 灰度图 → 特征点与描述符 → 匹配结果 → 目标坐标**。所有处理均在 CPU 内存中完成，避免了 GPU 与 CPU 间的数据拷贝。

## 4. 核心模块功能描述

### 4.1 屏幕捕获模块

基于 `dxgi-capture-rs` 库实现。该库直接调用 Windows DXGI Desktop Duplication API，能够以极低开销获取桌面画面的完整像素缓冲。模块输出为 **BGRA 格式的连续内存块**，包含每个像素的蓝、绿、红、Alpha 通道值，捕获延迟通常在 1~3 毫秒。

### 4.2 图像缩放模块

由于 2K（2560×1440）原始画面像素量巨大，直接进行特征提取会严重拉高延迟。本模块使用 `image` crate 的高性能重采样函数，将全屏画面缩小到固定的处理尺寸（例如 640×640 或 416×416）。缩放算法可选用 Lanczos3 或 Bilinear，前者边缘保持更好，后者速度更快。该步骤在 CPU 上完成，延时约为 3~5 毫秒，且缩放后的图像直接供后续模块使用，无额外数据搬移。

### 4.3 特征检测与匹配模块

该模块是整个检测管线的核心，由 OpenCV 的 Rust 绑定 (`opencv-rust`) 提供能力支撑。主要完成以下工作：

- **灰度转换**：将 RGBA/BGRA 图像转为单通道灰度图，作为特征提取的输入。
- **ORB 特征提取**：对模板图像和屏幕图像分别检测关键点并计算 ORB 描述子。ORB 算法对旋转具备天然不变性，且计算速度远超 SIFT/SURF。
- **描述符匹配**：使用汉明距离暴力匹配器，将模板描述子与屏幕图像描述子一一配对，筛选出最相似的特征点对。

为控制计算量，可限制每帧提取的特征点上限（如 500~1000 个），并根据模板大小动态调整。

### 4.4 多尺度金字塔策略

ORB 本身不具备尺度不变性，因此需要引入图像金字塔来模拟 mstpl 的尺度搜索能力。模块会以缩放后的屏幕图像为基底，通过反复高斯下采样构建 3~5 层的图像金字塔（每层缩小 0.8 倍）。在金字塔的每一层上，独立运行 ORB 特征提取与匹配，从而检测不同尺寸下的目标。最终选择匹配得分最高的一层作为该帧的检测结果，并根据该层的缩放因子将坐标映射回原始屏幕空间。

### 4.5 几何验证与定位

原始的特征点匹配通常包含大量误匹配。本模块通过 **RANSAC 单应性估计** 对匹配点对进行一致性检验：计算模板特征点到屏幕特征点的变换矩阵，并统计符合该变换的内点数量。只有当内点数量和内点率超过预设阈值时，才认为检测有效。最后利用内点集合计算出目标在屏幕上的中心位置和大致边界框，作为输出。

## 5. 检测流程详述

完整的单帧检测流程如下：

1. **离线阶段**：加载目标模板图像，将其缩放到标准尺寸，提取 ORB 特征描述符和关键点并保存。此步骤仅执行一次。
2. **在线阶段**（每帧循环）：
   - 捕获当前桌面画面，获得原始 BGRA 缓冲区。
   - 将缓冲区缩放为预设的处理尺寸（如 640×480），并转换为灰度图。
   - 构建 3 层图像金字塔（原尺寸、0.8×、0.64×）。
   - 对金字塔每一层执行 ORB 特征提取，与模板描述符进行匹配，并使用 RANSAC 计算内点率和目标位置。
   - 比较各层的置信度得分，选出最优层。
   - 根据最优层的缩放系数，将检测到的坐标映射回原始 2K 屏幕分辨率，得到最终的目标区域。
   - 输出目标位置、尺寸、置信度，供下游模块（如自动化点击、日志记录等）使用。

## 6. 性能与延迟分析

在典型桌面 CPU（如 Intel i5/i7 较新一代）上，以 2560×1440 输入、640×480 处理分辨率、3 层金字塔为例，各阶段延时估算如下：

| 阶段 | 延时 (ms) | 说明 |
|------|-----------|------|
| 屏幕捕获 | 1~3 | DXGI 直接取显存缓冲 |
| 图像缩放 | 3~5 | CPU 重采样，可采用快速算法降至 2ms 内 |
| 金字塔构建 | 1~2 | 2~3 次降采样操作 |
| ORB 特征提取 (3 层) | 5~8 | 可通过限制特征点数量进一步压缩 |
| 匹配与验证 | 1~2 | 暴力匹配 + RANSAC |
| **总计** | **11~20** | 完全满足 20ms 级低延迟要求 |

若进一步采用 `fast_image_resize` 库替代通用 resize，或使用 Bilinear 插值，总延时有望控制在 10ms 以内。

## 7. 优化策略

为适应不同性能需求的场景，可采取以下优化手段：

- **限制特征点数量**：对于尺寸较小的模板，将 ORB 特征点数降至 300~500，可大幅减少特征提取和匹配耗时。
- **缩减金字塔层数**：如果目标尺度变化范围有限（如仅 0.8~1.2 倍），只需 2 层金字塔即可，减少约 1/3 计算量。
- **ROI 区域检测**：当已知目标大概率出现在屏幕某个固定区域（如游戏小地图），可先裁剪该区域再送入管线，避免全屏处理。
- **帧间追踪与跳帧**：连续检测时，可仅在关键帧进行全搜索，中间帧利用上一帧位置做小范围跟踪，进一步平摊延迟。
- **内存重用**：在循环中避免反复分配图像缓冲区、Mat 对象，使用预分配内存池降低分配开销。
- **并行化**：金字塔各层的特征提取任务互相独立，可利用 `rayon` 等并行库进行多线程加速。

## 8. 总结

本方案构建了一条纯 CPU 的低延迟屏幕目标检测管线，通过组合 `dxgi-capture-rs`、`image`、OpenCV ORB 与图像金字塔，成功模拟了 mstpl 多尺度鲁棒检测的核心思想，同时避免了 GPU 依赖和过高的计算负载。它能够在 20ms 内完成一次完整的“截图-缩放-多尺度特征匹配-定位”流程，可稳定检测带有旋转、缩放和部分遮挡的 UI 元素，适用于实时性要求苛刻的 Windows 桌面应用场景。
